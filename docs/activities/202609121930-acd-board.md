# ARI queue integration into the operations board

## Objective and initial evidence

The user's Google 6007 → 6599 test appeared on the extension but not the new queue.
The pilot uses ARI/Stasis, not native Queue(), and the board only consumed native
AMI queue state. The prior read-only investigation confirmed the correct context,
an admitted visit and a 30-second timeout. Existing dirty work in both repositories
was preserved; no previously pending code was reverted or silently published.

## Local implementation

- Panel 0.12.0: private ACD snapshot sources, manager checks before/after reading,
  bounded single-flight cache, private VPN/loopback endpoints, no redirects and
  fixed read-only requests. Source configuration is not controlled by the browser.
- Explicit ACD catalog and visit projections join the existing board observation,
  inventory and flow pipeline. Keys retain context/queue; node is observed source,
  not a queue-registration restriction. Exact channel IDs join the AMI graph only
  with matching node/context/name. No number-based or cross-node inference.
- Greeting, waiting, announcement, offer and connected phases remain distinct.
  Cards show pending/in-service visit counts, not the number of agent legs.
  Stale/failing sources retain names without callers or live counts; older
  controllers support counts-only display with an explicit compatibility message.
- Context, node, text, busy and observed-activity filters work with ACD data;
  manager-wide view still needs no context selection. Source warnings stay inside
  the dedicated board's options menu. Existing SUI layout and popup preserved.
- ACD 0.10.1: additive visit channel identity and an optional distinct monitoring
  credential limited to scoped GET snapshots. Management routes and writes are
  forbidden for that identity. Existing management authentication stays compatible.
- Fixed an additional misleading label: channel Up means Channel answered, not
  that the caller is already conversing with an attendant. EN/PT copy checked.

## Read-only live check

Google's existing private snapshot API returned the expected context and node,
`controllerConnected=true`, seven shared queue definitions including the 6599
pilot, and zero visits waiting/connected at sampling (2026-09-12 19:25 -03).
The response has no `visits` collection, confirming the counts-only compatibility
path. Authentication used its existing private key without printing/copying the
secret. No call was originated and no remote file or service was changed.

## Delivery boundary

Implementation is local only: no deployment, key provisioning, commit, push,
database migration, Asterisk restart/reload or routing change. Full live channel
correlation requires the updated controller snapshot. Its local source includes
previous unshipped 0.10 queue operations/migration 007, so the older production
pilot must not be overwritten blindly. That rollout and physical acceptance remain
separate. The panel also needs private `Panel:AcdSources` configuration.

Permanent contracts: [ACD board integration](../acd-board-integration.md),
`.impeccable/acd-board.md`, and sibling
`sufficit-telephony-acd/docs/contracts/board-monitoring.md`. The development skill
guided checkpoint/evidence tracking; Sufficit frontend and Impeccable hardening
guided existing SUI reuse, explicit unavailable states and browser validation.
