# Resizable board sections

## Request and starting state

Add drag-resizable space for extensions, trunks and queues with browser-local
persistence. Existing OperatorBoard had fixed column/section gaps. The worktree
also contains unfinished customer-access changes; they were preserved, not
published as part of this task.

## Implementation

- Accessible column and row separators inside OperatorBoard, matching existing
  SUI colors and dense mosaic layout. English and Portuguese labels/tooltips.
- Small fingerprinted JS module with Pointer Events/capture, animation-frame
  updates, keyboard controls and component cleanup. No server calls during drag.
- Bounded proportions in localStorage, versioned schema, corrupt-data handling
  and usable session-only behavior if browser storage is blocked.
- Automatic content-based sidebar sizing remains the default; manual height
  selection persists until reset. Width/height are constrained to preserve usable
  sections, including after viewport or fullscreen changes.
- Below 901px, existing responsive stacking remains; desktop preferences are
  preserved. Resizing does not change URL filters, grants or telephone data.

The first fixed default row ratio failed the existing short-trunk-list contract.
It was replaced with automatic sizing until an explicit drag. Viewport height
now uses CSS rather than waiting for a resize-event callback; both regressions
passed afterward. Skills kept the existing SUI/Operate layout and keyboard access.
